## 7. Architecture
Native simulation owns authority. `KtwCampaign` owns deterministic campaign state, `KtwController` owns engine entities and the scene bridge; GUI submits network commands. Campaign and battle are distinct native sessions. Added in this increment: `KtwPolitics`, explicit `KtwBattleBridge`, save schema 2 with migration from schema 1. See `ARCHITECTURE.md` and `SPEC_CONTINUATION.md`. Windows shell is a separate C++ launcher; it invokes the unchanged official R28 with `-writableRoot -mod=public -mod=kazakh_total_war`. Config/saves live under runtime/binaries/data, isolated from installed 0 A.D. The NSIS front end invokes 64-bit Windows PowerShell, which verifies downloads and runs a temporary private Python worker. The worker validates the payload, extracts official data, verifies 140 runtime files and ZIP CRC, and checks the launcher before atomically publishing a new game directory. It refuses an existing unowned nonempty directory. Matching same-version installations can repair their registration without replacing game files or saves. Uninstallation only deletes unchanged owned files; saves/config and unknown or modified files remain.

## 9. Known bugs and risks
Native VFS hot reload during writes can produce transient truncated-script errors: freeze files and restart before acceptance runs. Old native saves use `OnDeserialized` migration, preserving the engine binary shape. Recovery locks campaign updates and KTW saving, but does not automatically pause base UnitAI/Attack; promptly load a prior save. Auto-result does not model commander deaths; old mid-battle saves have no commander entities. Map boundaries are schematic and do not establish historic sovereignty. Game title commercial clearance remains open. Official R28 omits imported VCRUNTIME140_1.dll; the installer downloads the pinned official Microsoft prerequisite and opens its original license UI if needed; only that prerequisite may request UAC. Native behavior remains unverified. Complete-runtime redistribution is not cleared: exact gloox 1.1-svn corresponding source and some Windows dependency grants/build correspondence remain unresolved. Bootstrap avoids repackaging those upstream binaries.
