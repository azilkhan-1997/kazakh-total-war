# Извлечение официального Windows runtime 0 A.D. Release 28

Дата проверки: 2026-11-07 UTC. Это фактическое извлечение оригинальных файлов движка, а не сборка нового Pyrogenesis из исходников и не результат запуска игры в Windows.

## Результат

Официальный установщик полностью загружен один раз и проверен по опубликованной SHA-256. Из его NSISBI-контейнера извлечены **140 файлов, 4 217 782 703 байта**: настоящий `binaries/system/pyrogenesis.exe`, DLL, конфигурация, локализации, Atlas, базовые игровые архивы, исходные уведомления о лицензиях и отладочные символы. Исполняемые файлы не переименованы; идентичность 0 A.D. сохранена.

Runtime в рабочем окружении: `upstream/windows-runtime/extracted-official-r28/` относительно родительской рабочей папки проекта. Извлечение выполнено за 58,64 секунды, без исполнения установщика, изменения реестра или создания его ярлыков/деинсталлятора.

## Почему обычные распаковщики не сработали

Воспроизведены ограничения имеющихся инструментов: 7-Zip 23.01/26.06 ранее отвергли флаги NSISBI `0x70`; `KokerZhou/NSISExtractor` на ревизии `8644b63d79a35bf002ba75f42375a9e4dafbbe74` интерпретировал начало solid-потока как длину отдельного заголовка и остановился на проверке размера. Эти инструменты не использованы для выдачи непроверенных файлов.

Официальный `source/tools/dist/0ad.nsi` содержит `SetCompressor /SOLID LZMA`. Сопоставление с настоящими исходниками NSISBI 3.09.1 (`nsis-code-7405-1-NSIS-trunk.zip`) подтвердило:

- `Source/exehead/fileform.h`: 36-байтовый первый заголовок, расширенные флаги, 64-битные смещения и длины данных; команды содержат восемь параметров.
- `Source/mtw/mtwdecompress.c`: последовательность независимых сжатых блоков с трёхбайтовой длиной little-endian и нулевым завершающим блоком.
- `Source/7zip/LZMADecode.c`: свойства LZMA в начале каждого блока.
- `Source/exehead/fileform.c`: solid-данные состоят из 64-битной длины и содержимого файла; файловая CRC32 вычисляется по содержимому, затем по восьми байтам длины.

Собственный ограниченный экстрактор `tools/extract_r28_nsisbi.py` использует только стандартную библиотеку Python и принимает **исключительно установщик с указанной SHA-256**. Он декодирует структурные сведения, отслеживает только пути файлов в проверенной секции и ничего не исполняет. Он проверяет границы, размер декодирования, EOF каждого LZMA-блока, отсутствие лишних данных, относительность путей, отсутствие коллизий, файловые CRC и CRC заголовков. Обрабатываются 2 013 блоков; суммарно декодировано 4 218 196 672 байта, включая служебные данные контейнера.

## Воспроизведение

Инструмент сохранён в `tools/extract_r28_nsisbi.py`, а проверенный манифест — в `docs/windows-runtime-manifest.json`. Сырые доказательства и исходный установщик находятся отдельно в `../upstream/windows-runtime/`. Из корня проекта:

```sh
python3 tools/extract_r28_nsisbi.py \
  ../upstream/windows-runtime/0ad-0.28.0-win64.exe \
  ../upstream/windows-runtime/extracted-official-r28
```

Целевая папка должна отсутствовать: частично полученный результат не переиспользуется. Потребуется приблизительно 5,9 ГБ для установщика и полного распакованного набора. Инструмент предназначен для данного зафиксированного дистрибутива, не заявляет совместимость со всеми вариантами NSISBI.

Доказательства:

- `extracted-official-r28-manifest.json`: URL, размер, SHA-256 источника, все 140 путей/размеров/SHA-256/CRC32, результаты проверки и статистика потока.
- `extraction.log`: журнал каждого извлечённого файла и итог `SUCCESS`.
- `zip-validation.json`: полная проверка каждого элемента ZIP.
- `0ad-0.28.0-win64.exe.sha256sum`: опубликованная контрольная сумма.

11 автоматических тестов `tests/test_nsisbi_extractor.py` прошли: чтение между блоками, усечённые/повреждённые данные, границы контейнера, ограничение словаря, лишние данные, недопустимые строки и отказ при неверной SHA-256 без создания выходной папки. Команда: `python3 -m unittest discover -s tests -p 'test_nsisbi_extractor.py' -v`.

Проверены все 2 013 элементов `mod.zip` и все 52 829 элементов `public.zip`: `ZipFile.testzip()` не обнаружил повреждений. Проверены CRC32 всех 140 файлов, CRC компилированного заголовка и CRC загрузчика установщика (`c5a801f5`).

## Поставка и остающиеся ограничения

В оригинале сохранены `license_dbghelp.txt`, `license_gpl-2.0.txt`, `license_lgpl-2.1.txt`, `license_mit.txt`. Лицензии конкретных DLL и материалов требуют отдельного аудита: GPL движка не заменяет условия `dbghelp.dll`, Microsoft runtime или медиаматериалов. Файлы инструментов распаковки не являются игровыми ассетами. NSISBI имеет собственный `COPYING`; его исходники не включены в runtime.

26 файлов `.pdb` занимают 534 913 024 байта. Это отдельные отладочные символы, которые можно хранить как диагностический комплект, не удаляя из первичного проверенного набора. Остальной оригинальный набор занимает 3 682 869 679 байт. Установщик дополнительно создаёт ярлыки, URL и деинсталлятор и пишет в реестр; для переносимой поставки эти операции намеренно не воспроизводятся.

**Обнаруженная зависимость:** `pyrogenesis.exe` импортирует `VCRUNTIME140_1.dll`, которой нет среди 140 файлов установщика. Поэтому полный переносимый набор и наличие Microsoft Visual C++ runtime нельзя считать подтверждёнными одним фактом извлечения. Нужен проверенный официальный redistributable/разрешённый app-local runtime и контроль зависимостей всех DLL; статус этой работы должен учитываться сборщиком поставки.

**Запуск:** Wine 9 сообщает версию, но создание Windows-процесса в данной среде блокируется на `wineserver: socket: Operation not permitted`. Ограничение не обходилось. Эта проверка не заменяет запуск на Windows 10/11. Извлечение и CRC-тесты подтверждают целостность настоящих файлов; они не подтверждают прохождение Windows-приёмки, работу графического драйвера, FPS, запуск собственного лаунчера или полный игровой цикл на Windows.
