# KAZAKH TOTAL WAR — Windows-комплект 0.3

SAYRAM PLANETA HOLDING · LEGACY OF THE STEPPE

В комплект входит настоящий `KazakhTotalWar.exe` для Windows x64, исходники и игровой модуль 0.2.0. Это техническая версия для проверки на ПК. Исполняемый файл собран; запуск игры на Windows 10/11 ещё не подтверждён. Известный игровой цикл проверен ранее на Linux в настоящем Pyrogenesis, а не в браузере.

## Первая установка

1. Полностью распакуйте ZIP в доступную для записи папку, например `C:\Users\ВашеИмя\Games\KazakhTotalWar`. Не запускайте файлы прямо внутри ZIP. Понадобится не менее 8 ГиБ свободного места.
2. Установите **CPython 3.11 или новее, Windows x64**, со стандартной библиотекой, с [официального сайта Python](https://www.python.org/downloads/windows/). Python нужен для первой распаковки и необязательного переноса сохранений; сама игра его не использует.
3. Запустите **`Setup-Windows.cmd`**. Он получает оригинальный установщик 0 A.D. Release 28 от Wildfire Games, проверяет размер и SHA-256, извлекает его как данные и сверяет все 140 файлов. Загрузка — около 1,62 ГБ; извлечённый движок — около 4,22 ГБ. Программа установки 0 A.D. не запускается.
4. Если показано сообщение о Microsoft Visual C++, вручную откройте полученный официальный `prerequisites\VC_redist.x64.exe` и завершите его установку. Это отдельный подписанный установщик Microsoft; он может запросить права администратора. Наш скрипт не устанавливает его автоматически.
5. Запустите **`KazakhTotalWar.exe`**. После завершённой установки сетевое подключение и Python для игры не требуются по архитектуре; этот офлайн-сценарий ещё должен пройти Windows-приёмку.

Интерпретатор можно указать вручную в PowerShell:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\Install-WindowsRuntime.ps1 -PythonExe "C:\Path\To\python.exe"
```

Для машины без интернета можно заранее принести подлинные установщики и использовать параметры `-InstallerPath` и `-VcRedistPath`. Они всё равно проходят проверку закреплённых контрольных сумм. Сведения об URL и размерах находятся в исходном скрипте. При несовпадении суммы установка останавливается; обхода проверки нет.

## Как проверить игру

В главном меню выберите новую кампанию. Переместите армию из Шу в Сарысу и завершите ход. Во встрече выберите «Сражаться», выделяйте войска рамкой и отдавайте приказы правой кнопкой мыши. После результата проверьте потери на карте, сохраните кампанию, полностью закройте игру и воспользуйтесь «Продолжить».

Для диагностики файлов и зависимостей:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\Test-Windows.ps1
```

Успех этой команды означает успешную предварительную проверку, а не прохождение битвы или тест графики. Полный сценарий находится в `docs\windows-acceptance-checklist.md`. Скрипты PowerShell подготовлены для Windows; их нативное исполнение здесь ещё не проверено.

## Сохранения и обновления

Профиль этого комплекта изолирован от обычной 0 A.D.:

| Данные | Путь относительно папки игры |
|---|---|
| Сохранения | `runtime\binaries\data\saves` |
| Настройки | `runtime\binaries\data\config` |
| Журналы движка | `runtime\binaries\logs` |
| Кэш | `runtime\binaries\data\cache` |

Закройте игру перед переносом. Для копирования старых сохранений KTW из стандартного профиля:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\Import-LegacySaves.ps1
```

Параметр `-Source "D:\MyOldGame\saves"` задаёт другую исходную папку. Инструмент проверяет формат, версию движка, идентификаторы кампании и мода, CRC и контрольную сумму копии. Он не удаляет исходники, не заменяет существующие сохранения и не создаёт дубликаты при повторном запуске. Приняты версии модуля 0.1.0 и 0.2.0; проверены четыре подлинных архивных сохранения. Проверка содержимого ZIP не заменяет загрузку каждой кампании движком на Windows.

Повторная установка не перезаписывает существующую папку `runtime`. Для следующей версии распакуйте новый комплект отдельно и перенесите сохранения после резервного копирования. Запускайте игру через `KazakhTotalWar.exe`: прямой запуск двигателя может использовать другой профиль.

## Что изменилось в 0.3

- Собственный нативный C++-запускатель: версии, Unicode-пути, диагностика отсутствующих файлов и VC runtime, изолированный профиль.
- Воспроизводимая сборка запускающего EXE и закреплённые зависимости компилятора.
- Проверенная распаковка официального NSISBI-контейнера с контролем целостности.
- Подготовлены установка, диагностика и безопасный перенос прежних сохранений.
- Исходный игровой модуль 0.2.0 и схема сохранений 2 сохранены. Новые графические эффекты и дополнительные войска в этом выпуске не заявляются.

## Текущие ограничения

Это установочный комплект, **не готовый архив полностью установленной игры и не принятый Steam-релиз**. Windows EXE не подписан. Запуск на Windows и проверки драйверов, звука, Unicode-путей и сохранений после перезапуска остаются открытыми. Wine в среде разработки не смог запуститься из-за запрета системного IPC; его результат не выдан за тест Windows.

Движок и компоненты Microsoft загружаются непосредственно от их издателей: в нашем ZIP их бинарники не перепакованы. Для будущего единого дистрибутива остаются точное соответствие исходников `gloox 1.1-svn` и условия распространения Windows-зависимостей. Подробности — `WINDOWS_DISTRIBUTION_NOTICES.md`. Лицензии собственного кода и импортированного искусства сохранены в `LICENSE_KTW.txt`, `THIRD_PARTY_NOTICES.md` и `LICENSES_KTW`.

Исходники с историей Git, тестами, реальными прежними кадрами и документом продолжения `docs/ASTRA_PROJECT_STATE.md` входят во вложенный архив `source`. Вторая часть разработки продолжает именно этот проект.
