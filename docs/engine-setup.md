## Воспроизведение на обычном Linux

Потребуются 64-разрядная Ubuntu 24.04, бинарный Pyrogenesis 0.28.0 и игровые данные той же версии. Стандартный пакет Ubuntu 24.04 предоставляет 0.0.26 и не подходит. Используйте официальный дистрибутив Release 28 либо WFG PPA с версией 0.28.0.

Исходные архивы распаковываются в одну директорию последовательно:

```sh
tar --no-same-owner -xJf 0ad-0.28.0-unix-build.tar.xz
tar --no-same-owner -xJf 0ad-0.28.0-unix-data.tar.xz
```

Не распаковывайте архивы одновременно в одну директорию и не запускайте игру до завершения распаковки. Release 28 использует `binaries/data/mods/mod/mod.zip` (93 421 350 байт) и `binaries/data/mods/public/public.zip` (3 508 827 314 байт). В `public.zip` проверено 52 829 записей; для `mod.zip` проверено 2 013 записей и CRC всех файлов.

Поместите папку `mods/kazakh_total_war` из проекта в пользовательскую папку модов 0 A.D. или в `binaries/data/mods/`, затем запустите:

```sh
pyrogenesis -mod=public -mod=kazakh_total_war
```

Для сборки C++-движка из исходников следуйте инструкции разработчиков: https://gitea.wildfiregames.com/0ad/0ad/wiki/BuildInstructions. В этой сессии **не выполнена собственная C++-сборка**: для интеграционного тестирования использован неизменённый бинарник WFG PPA. Исходники движка получены и изучены отдельно.

## Команда проверки генерации карты

```sh
pyrogenesis -mod=public -mod=kazakh_total_war \
  -autostart=random/ktw_campaign -autostart-seed=1465 \
  -autostart-players=2 -autostart-size=256 -autostart-victory=endless
```

Это только проверка генерации и загрузки карты. Стандартный автозапуск не передаёт пользовательские настройки `KtwMode`, поэтому он сам по себе **не проверяет игровой цикл кампании**. Для игрового цикла используйте главное меню проекта и «Новая кампания».

Параметры проверены по реальному `autostart/cmd_line_args.js` Release 28. Формат пути карты — `random/ktw_campaign`; параметр зерна — `-autostart-seed=1465`. Параметр `-autostart-random` для этой задачи не используется.

## Особенности среды проверки

Рабочая среда — Linux в ограниченном пользовательском пространстве имён с единственным отображённым UID 0. Игра запрещает запуск при `geteuid()==0`; системные привилегии хоста при этом отсутствуют. Только в локальной QA-среде применён маленький LD_PRELOAD shim, возвращающий UID 1000 для этой проверки. **Он не входит в игровой мод, не нужен на обычном ПК и не должен включаться в Windows-поставку.**

Графический запуск выполнен через Xvfb, OpenGL и Mesa llvmpipe. Xvfb и игра работают в одном процессе-окружении, поскольку каждый запуск команд имеет отдельное сетевое пространство имён. Скриншоты получены захватом реального окна игры. Такие проверки подтверждают запуск и визуальную корректность, но **не являются измерением производительности на видеокарте**.

## Windows: статус продолжения 0.3

Прежний барьер NSISBI устранён: собственный статический экстрактор извлёк 140 файлов официального Release 28, проверены CRC контейнера, заголовков, файлов, обеих ZIP-баз и SHA-256. Настоящий AMD64 `KazakhTotalWar.exe` собран из C++ с повторяемым результатом. См. `windows-runtime-extraction.md` и `../launcher/windows/README.md`.

Текущая поставка — bootstrap-комплект. `Install-WindowsRuntime.ps1` получает закреплённый официальный установщик на ПК пользователя, извлекает проверенные данные в отдельный профиль и добавляет существующий мод. Windows-подготовка требует CPython 3.11+; он не нужен при последующих запусках игры. Microsoft VC prerequisite получается непосредственно от Microsoft и устанавливается пользователем через его штатное окно.

Нативная Windows 10/11 среда здесь отсутствует; Wine не прошёл инициализацию из-за запрета UNIX IPC. Не выполнены Windows запуск, проверка драйверов, полный игровой цикл и сохранения, антивирусная репутация, цифровая подпись и Steam upload. Контроль файлов не заменяет этих проверок.

Полный runtime не перепакован в распространяемый ZIP: точная gloox SVN-ревизия и часть условий распространения зависимостей ещё не закрыты. Конкретный аудит — `WINDOWS_DISTRIBUTION_NOTICES.md`; инструкция игроку — `README_WINDOWS_RU.md`. Исходное ядро кампании/битв не изменялось после v0.2.
